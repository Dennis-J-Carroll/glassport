# HTTP Gate: transport enforcement plan

**Status:** Proposed handoff plan, 2026-09-23
**Base inspected:** `fix/priority-streaming-foundation` at `0a04ece`
**Goal:** Make `glassport gate --transport http --url <remote>` enforce the same narrow rule as the stdio gate: block a `tools/call` whose name is excluded by a complete, correlated, current `tools/list` declaration for that caller. Keep `glassport wrap --transport http` byte-forwarding and passive.

## Status after #80 and the gate-admission PR (2026-09-23)

This plan was drafted against `0a04ece`, before #80 merged. Several "facts"
below describe that older base (for example "`tap.main()` currently rejects
HTTP gate mode"). Measured against `main` at `ba20261` with loopback probes:

**Already delivered by #80.** Per-epoch private logs (plan: per-scope logs);
opaque HMAC credential partitions over `Authorization`/`Cookie`/`Proxy-Authorization`;
provisional `initialize` binding to `Mcp-Session-Id`; the decision journal
(intent before delivery, actual outcome after); zero-upstream local blocks
with exact-id `-32000` responses; `gate --transport http` CLI.

**Closed by the gate-admission PR.** Phase 3's bounded inspection and §7
endpoint checks. In gate mode only: `413` over the inspection cap (4 MiB,
tied to the observer's frame limit so nothing forwarded is unanalysed),
`415` for `Content-Encoding`, `400` for anything but one unambiguous JSON
object, `403` for a non-loopback `Host` or foreign `Origin`. Before this,
nine request shapes carried an undeclared call upstream in gate mode,
including duplicate `name` keys (a first-wins/last-wins parser differential).

**Still open.**
1. **Stateless 2026 routing (§Scope 2).** A POST without `Mcp-Session-Id`
   gets a private one-request epoch, so a stateless server's `tools/list` never
   informs a later `tools/call`. Stateless traffic is observed but never
   enforced. Needs identity decisions (tenant/auth headers, anonymous scope,
   version detection) and must ship with `(http_exchange_id, jsonrpc_id)`
   correlation.
2. ~~**Id-less `tools/call`.**~~ Decided: `400` in gate mode as invalid MCP
   input (`invalid_mcp_request`, distinct from a policy block); null and
   non-string/integer ids too. Observe and `wrap` still forward.
3. ~~**Freshness.**~~ #84: server `list_changed` and wire-clock `ttlMs`
   expiry retire the surface to unknown. The stdio Gate is unchanged.
4. **2026 header/body match (§Adapter 3), in-flight `tools/list` hold,
   per-scope HTTP control files, version-aware `premature_call`.**

## Decision and scope

Build an HTTP enforcement coordinator around the existing `MCPTraceBuilder(retain_events=False)`, `SessionState`, `DetectorEngine`, and `policy.decide(..., block_fabricated=True)`. Give each independently authorized HTTP scope its own coordinator and log. The HTTP adapter owns framing, routing, delivery, and synthetic HTTP responses; the detector and policy remain transport-free. Keep the stdio `Gate` and its CLI behavior unchanged in this increment. Refactor both transports onto one enforcement core later, after HTTP behavior is proven.

Do **not** pass one `Gate` instance to `_make_handler`. Current `Gate.observe_s2c()` accepts any `result.tools` without correlating it to a `tools/list` request, replaces rather than assembles paginated lists, and keeps one global surface. A threaded HTTP proxy could then transfer one caller's declaration to another. The new session builder already solves correlation, unknown-versus-empty, and pagination.

The first blocking rule remains **fabricated tool call only**. PII, egress, schema, and context findings are warnings; their severity alone must not trigger a block. No policy DSL, broad content filtering, upstream authentication service, or stdio gate migration in this change.

## Facts that shape implementation

- `tap.main()` currently rejects HTTP gate mode. `run_http_tap()` opens one process-wide log and `_make_handler()` handles concurrent POST/GET/DELETE requests. `_read_client_body()` logs before forwarding and streams request bytes beyond `_MAX_LOGGED_BODY`; `_relay()` never inspects a JSON-RPC method.
- JSON responses are streamed in chunks; SSE events are framed for logs *after* bytes are forwarded. Named SSE events already parse into JSON-RPC frames. `SessionLog.record()` serializes entries but does not return their sequence or delivery outcome.
- `MCPTraceBuilder.ingest_frame()` correlates request IDs in direction-specific maps and updates `SessionState`. `SessionState.surface is None` means unknown, malformed, oversized, or incomplete declaration; `frozenset()` means a proven empty declaration. `DetectorEngine` yields event-local findings. `policy.decide()` blocks only a severity-3 `fabricated_tool_call` supported by an observed surface. The builder currently keys pending requests by JSON-RPC ID, which is insufficient when independent HTTP POSTs in one authorization scope reuse an ID.
- Existing HTTP relay hardening covers framing, hop headers, stream bounds, and connection cleanup. Gate work must keep those properties. Existing `tests/test_http_tap.py::test_gate_over_http_rejected` becomes a positive dispatch test.
- MCP transport versions differ. The [2025-11-25 Streamable HTTP spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) permits `Mcp-Session-Id`, GET SSE, DELETE, and resumability. The [2026-07-28 Streamable HTTP spec](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) removes transport sessions and GET/DELETE, requires request metadata headers, and keeps POST responses as JSON or request-scoped SSE. Both eras matter; a design keyed only by `Mcp-Session-Id` leaves current stateless traffic ungated.

## Enforcement contract

| Evidence at call time | Action | Wire behavior |
| --- | --- | --- |
| Complete current list includes name | Allow, plus any warning findings | Original POST and response pass through |
| Complete current list excludes name | Block | Upstream receives zero request bytes; client receives one JSON-RPC error for original ID |
| List explicitly empty | Block every valid `tools/call` | Same synthetic response |
| No list, partial pagination, invalid/oversized list, expired list, unproven scope, or fabricated detector failure | Skip enforcement with reason | Original request passes; never invent exclusion evidence |
| Gate control explicitly disabled | Record disabled decision | Original request passes |
| Malformed/ambiguous HTTP or JSON framing in gate mode | Reject as transport input error | No upstream request; never silently forward opaque `tools/call` payload |

For a blocked JSON-RPC request, return HTTP `200` with `Content-Type: application/json`, a correct `Content-Length`, and the existing `-32000` error body with `error.data.glassport = "gate_blocked"`; preserve original JSON-RPC ID type/value. Do not copy upstream `Mcp-Session-Id` or other upstream response headers onto a locally generated response. An id-less `tools/call` is invalid MCP request shape; reject it as a `400` input error rather than fabricate an unmatchable response. This is an HTTP-specific improvement over stdio's id-less behavior, not a new enforcement rule. Use fixed, sanitized messages; never echo tool arguments, credentials, or arbitrary header values.

For a call while a matching `tools/list` request is in flight, wait on that scope's condition for at most the existing 2-second hold window; do not hold the scope lock while waiting. If no list is in flight, skip immediately. Timeout forwards with `gate_skipped: no_surface_timeout`. A blocked call must not open an upstream connection. Already forwarded calls cannot be retroactively blocked.

## Scope and lifecycle model

1. **2025 sessionful traffic:** create a provisional context for `initialize`; when its correlated response supplies an upstream `Mcp-Session-Id`, bind that context to the ID before later requests use it. Require subsequent requests to resolve to the same context. Never log the raw session ID. GET SSE, resumed GET, POST SSE, and DELETE for that ID feed one context. On successful DELETE, upstream 404, idle expiry, or proxy shutdown, finish and evict it.
2. **2026 stateless traffic:** scope `tools/list` and `tools/call` by fixed upstream URL, protocol version, and authorization identity. The [2026 tools spec](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) permits tool sets to vary by request authorization, not by connection. Derive an in-memory keyed fingerprint from `Authorization`, `Cookie`, and configured tenant/auth header names; assign a random opaque `scope_id` for logs. No raw credentials, cookie values, or stable credential hashes on disk. An anonymous caller uses a public scope only for a conforming 2026 server. Connection address/port and JSON-RPC ID are **not** identities.
3. **2025 without session ID:** use an authorization scope only when deployment explicitly opts into that assumption. Otherwise preserve observation and mark `gate_skipped: unproven_scope`; do not combine different connections into one authoritative declaration.
4. **Ambiguous identity:** changed credentials, duplicate conflicting identity headers, unsupported protocol version, or an exhausted scope table must never inherit another scope's surface. Use a fresh unknown scope or reject malformed headers. Cap active scopes, idle lifetime, pending requests, declaration size, and body bytes. Eviction discards authority; it never changes unknown into empty.
5. **Tool-list freshness:** accept only a correlated successful response for the same scope. Assemble all pagination pages before the surface becomes known. Invalidate on `notifications/tools/list_changed`, a changed authorization identity, session end, or configured maximum age. Honor valid `ttlMs` up to a conservative ceiling; absence of TTL uses that ceiling. A new list supersedes an old one only when complete. Retain supporting declaration sequence for every block.

Guard context state with a per-scope lock. Assign one sequence and feed one event under that lock, so concurrent POST/SSE/GET updates and policy decisions have a reproducible order. Release lock before network I/O or condition waiting. Give each HTTP POST a random `http_exchange_id` in its wire entries. Teach builder correlation to prefer `(http_exchange_id, JSON-RPC ID)` for HTTP responses, retaining today's JSON-RPC-ID-only behavior for stdio. A modern POST response is tied to its own exchange; two concurrent callers with the same authorization and reused ID cannot cross-pair. For a legacy resumed GET, maintain a bounded `Last-Event-ID` to originating exchange map; if origin cannot be proved, log the event but do not treat it as a tool declaration. A blocked response and any observed upstream response retain their originating scope. Avoid retaining entire event history: builder uses `retain_events=False`; persisted wire is the replay source.

## HTTP adapter changes

1. Add explicit `enforce`/control options to `run_http_tap()` and pass a coordinator into `_make_handler()`. Keep default parameters passive for existing callers and tests. CLI accepts `gate [--controllable] --transport http --url ...`; `wrap` continues to select the old passive path. Reject incompatible extra CLI arguments with a clear usage error.
2. In gate mode, read each POST body to a configurable bounded inspection limit **before** any upstream connection. Default limit should be documented and covered by tests (suggest 4 MiB, consistent with common MCP server limits). Reject larger bodies with `413`, unsupported content encoding with `415`, and ambiguous Content-Type/length or malformed single-message UTF-8 JSON with `400`. Preserve the passive adapter's streaming behavior. Determine method from the parsed body, never from `Mcp-Method` alone.
3. For 2026 requests, compare required `MCP-Protocol-Version`, `Mcp-Method`, and decoded `Mcp-Name` headers with body fields before enforcement and forwarding. Reject mismatches with `400`; treat header names case-insensitively and values case-sensitively. Forward `Mcp-Param-*` untouched; full custom parameter-header validation belongs to a separate rule because this gate does not route or decide from those headers.
4. Observe requests and responses through one helper that makes the exact JSONL entry used by both the live builder and `SessionLog`. Do not tail the file to decide. Include opaque `http_exchange_id` on each POST and its response events. A response can establish a declaration only after its complete JSON object or complete SSE event is delivered to the client. Truncated JSON, partial SSE, oversize SSE events, and upstream errors leave the surface unknown or previously invalidated. Keep SSE bytes streaming; never buffer a whole long-lived stream to decide. Make context warnings version-aware: 2026-07-28 has no `initialize` handshake, so absence of `notifications/initialized` is not `premature_call` evidence for that version.
5. On a blocked call, log the original c2s frame with `gate.action = "blocked"` and the injected s2c error with `gate.action = "injected"`. On forwarded calls, log `gate_skipped`/`gate_disabled` where applicable. Add a `glassport.decision` record keyed by `scope_id` and wire `seq`: policy version, rule/reason, supporting declaration sequence, selected action, actual outcome (`blocked`, `forwarded`, `upstream_failed`, `client_disconnected`), and fixed diagnostic codes. The existing adapter already ignores `glassport.*` records. No duplicate raw payloads in decision records.
6. Use a private per-scope JSONL log in gate mode, named by random scope ID. This keeps existing `from_mcp_session_file()`, report, SARIF, and TUI replay semantics intact without teaching them to disentangle one multiplexed log. Keep the current one-log behavior for passive HTTP. A small run manifest can map opaque scope IDs to filenames and versions; never include raw credentials. Logging failure warns loudly but must not turn a known, valid block into an allow: in-memory enforcement continues, matching stdio Gate behavior. Record best-effort health counters and mark replay incomplete.
7. Apply local HTTP endpoint checks before any forwarding: default loopback bind, valid `Host` for the bound endpoint, and `Origin` validation with `403` on invalid present Origin. Both [2025](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) and [2026](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) require Origin validation for HTTP servers. Test browser-origin and DNS-rebinding shapes. Keep upstream authorization and session headers forwarded as today, except hop-by-hop headers.

## Delivery and failure rules

- Treat a policy block as a local response, not an upstream error. Close/drain client request framing safely so a keep-alive connection cannot reinterpret leftover bytes. Do not start the upstream call, even transiently.
- A detector exception produces a warning and cannot establish a block by itself. If the fabricated-call detector failed or state/correlation became limited for that event, record a fixed `analysis_error`/`correlation_limited` skip reason and forward. Do not surface exception text from untrusted input.
- If request inspection exceeds its explicit gate-mode bound, return `413` before forwarding. This bounded rejection is visible and distinct from a fabricated-call policy block. If a response exceeds inspection bounds, forward bytes unchanged and discard its authority; do not turn truncated `tools/list` into an empty list.
- Client cancellation/disconnect stops that request's upstream work when possible, closes response and connection, and records actual outcome. Do not ingest an undelivered declaration as though client saw it. For 2025 GET/SSE, keep session state until DELETE/expiry; for 2026, closing a POST response stream is cancellation.
- Gate control for HTTP should be per scope, using owner-only `.gate` files and the existing safe override semantics. Check control only when a block is otherwise justified, and emit `gate_disabled` evidence for calls forwarded because of it. Preserve TUI control expectations for each scope log.

## Exit criteria

- `glassport gate --transport http --url ...` blocks only proven fabricated calls in a demonstrably isolated scope; `wrap --transport http` remains passive.
- Every block has original call, supporting declaration, injected response, and actual delivery outcome in a private replayable scope log. A test proves blocked calls cause **zero** upstream requests.
- Modern stateless and legacy sessionful protocols both have tested routing. Unsupported or ambiguous identity is marked and forwarded without a false block.
- Full suite and existing HTTP relay/security tests pass. No new runtime dependency. No release claim until implementation branch is reviewed and CI passes.

## Main risks to review with Opus

1. **Identity model:** custom upstream auth/tenant headers can change authorization without changing `Authorization` or `Cookie`; expose configured scope headers, and never claim enforcement for an unverified identity.
2. **Replay ordering and correlation:** log writes, live builder ingestion, and concurrent stream delivery must agree on one per-scope order. JSON-RPC ID alone cannot correlate independent HTTP exchanges; resumed GET may lack proof of the originating POST. A shared process-wide log without scope partitioning cannot prove this.
3. **Stale authority:** list changes, pagination, TTL, and delivery failure can make a formerly known surface unsafe to enforce. Unknown must remain distinct from empty.
4. **Version drift:** current MCP removes session IDs and introduces header/body matching. Tests should exercise both version families rather than treating GET/DELETE as universal.
5. **Gate semantics:** this change blocks undeclared tool *names*. It does not prevent a declared tool from leaking secrets or reaching an unexpected host; those detectors remain warnings until separate, explicit policy rules are designed.

## Stateless routing: decided design and phases (2026-09-23)

Owner decisions: scopes are keyed on credentials plus **explicitly configured**
tenant headers; anonymous callers share authority **only by opt-in**
(`--public-surface`); protocol version comes from explicit metadata checked for
consistency; unknown versions never inherit authority.

Spec facts (2026-07-28 Streamable HTTP): no sessions, GET, DELETE or
resumability; every POST carries `MCP-Protocol-Version`, which must equal
`params._meta["io.modelcontextprotocol/protocolVersion"]`; `Mcp-Method` is
required, and `Mcp-Name` (base64 sentinel `=?base64?…?=` decoded before
comparing) for `tools/call`, `resources/read`, `prompts/get`. Mismatch or
missing → `400` / `-32020 HeaderMismatch`. `list_changed` arrives only on a
separate long-lived `subscriptions/listen` POST stream. Intermediaries that
enforce policy should reject versions that do not require header/body
validation rather than trust the headers.

Hazards found in the current code, which the design must remove:
- Builder correlation keys pending requests and **permanent** quarantines by
  JSON-RPC id. In a shared scope every client's `id: 1` collides, so after the
  first collision no `tools/list` could establish a surface. Correlation must
  key on `(exchange, id)`.
- An HTTP context's `lost` flag is sticky. One malformed frame from one caller
  would switch enforcement off for the whole shared scope. A shared scope must
  recover: a loss makes the surface unknown until the next complete list,
  instead of retiring authority forever.

**S1: modern request admission (gate mode)** — *built; `--endpoint-era auto|legacy|modern` added per owner decision so the operator, not the agent, decides whether legacy traffic is allowed.* Classify each POST by
`MCP-Protocol-Version`: absent or a known legacy version → existing sessionful
path; `2026-07-28` → modern; any other value → `400` (an agent-chosen header
must not route around enforcement). For modern requests: single, well-formed
headers; `_meta` version equals the header; `Mcp-Method` equals `method`;
decoded `Mcp-Name` equals `params.name`/`params.uri`. Refusals carry a
JSON-RPC `-32020` body so modern clients do not fall back to `initialize`.

**S2: scope routing and exchange correlation.** `HTTPObserver(scope_headers=…,
public_surface=…)`; CLI `--scope-header NAME` (repeatable) and
`--public-surface`. A modern POST routes to scope key `(version, HMAC(credential
headers + configured scope-header values))`. Anonymous → public scope only with
`--public-surface`, otherwise a private request epoch with a non-enforceable
`unproven_scope` diagnostic. Duplicate credential or scope headers → unproven.
Every POST gets an opaque exchange id; entries carry it and the builder keys
pending/quarantine on `(exchange, id)`. Scope losses make the surface unknown
without making the scope permanently lost. `subscriptions/listen` streams with the
same credentials feed the same scope, so `list_changed` retires it (#84).

**S3: end-to-end enforcement tests and docs.** Two concurrent callers in one
scope reusing ids; two credential scopes and two tenant values with different
lists; anonymous with and without `--public-surface`; `list_changed` via a
listen stream; unknown version; header mismatch; a malformed frame in a
shared scope does not disable it for other callers.
